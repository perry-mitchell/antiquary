# Agent Rules

Ensure you follow, as a coding/review/general agent, all of the rules and guidance laid out in this file and ALL subsequent `AGENTS.md` files in any directory you come across.

## General rules

- When creating commits/PRs, never assume something is a breaking change. The user will specify this.
- We merge squash style, so PR titles must use conventional format: `fix(xx): ...` / `feat(yy): ...`.
- Never assume authorship for some work. Everything produced belongs to the git owner on the current machine.
- Keep documentation and comments concise and short, in all scenarios, unless instructed otherwise.
- Write tests (including E2E) for new functionality wherever viable.
